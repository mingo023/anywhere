# Spaces: one sidebar space per machine

> **For Claude:** run with `/brainless docs/plans/2026-11-18-spaces.md`. Each section below is one commit-sized unit; land them in order.

**Goal:** Projects on several machines stay manageable. Each machine (this Mac, every SSH host) is a *space*: the sidebar shows one space at a time, a switcher at its bottom moves between them, and everything that starts work (composer, add folder, clone) acts on the space on screen.

**Design reference:** `.ui-review/prototypes/spaces.html` (open it; the Walk through panel jumps to each state). Earlier explorations: `sidebar-machines.html` (why Spaces over project-first or sections), `composer-machine-picker.html`, `host-finder.html`.

**Decisions already made:**
- Spaces, as Arc does: one machine at a time, switcher at the sidebar's bottom, ⌃1–⌃9 and a two-finger horizontal swipe to switch, a badge on a space counting sessions there waiting on the user.
- The composer's machine is the space on screen. Picking another machine in its machine pill switches the space, so there is only ever one "current machine".
- Each space has a colour (default from a palette by position, changeable in the space menu). It tints the space's icon in the header and marks it in the switcher.
- A host terminal that no saved project holds no longer becomes a project of its own (the "phantom projects" bug). Showing such sessions inside their host's space is later work (Not in scope).
- Repos are matched across machines by folder name for now (switching space picks the same-named project there, else the first).

**Not in scope:** a "Not added" group of a host's own sessions in its space; dragging spaces to reorder; Cloud; cloning onto a machine from a project's menu on another machine.

**Toolset** (run from `packages/desktop`):
- Build: `cargo build --workspace`
- Lint: `cargo clippy --workspace --all-targets`. Must add no warnings (the existing ones in `git.rs`, `inbox.rs`, both `open_in.rs` are not ours).
- Tests: `cargo test --workspace`; one area: `cargo test -p pocket spaces`.
- Screens: from the repo root, `FIXTURE_HOST_FILES=1 .ui-review/fixture/capture.sh <dir> <name>=<step>,<step> …` writes `<dir>/impl-<name>.png`. The fixture's fake `devbox` host answers `status`, `fs.list`, `fs.read`, `fs.stat`, `list`, `accounts` and the composer's git commands, and has `app-ios` registered as a project.

**Read first:**
- `CLAUDE.md` and `docs/adr/0003-desktop-code-layout.md`: model crates hold logic, `pocket` holds views, one module per feature with its own state struct, `impl Desktop` stays thin, tests beside the logic named as sentences.
- `crates/project/src/project.rs`: `projects()` decides what the sidebar lists.
- `crates/pocket/src/sidebar.rs`, `sidebar/sections.rs`, `sidebar/rail.rs`: the aside, its sections, the compact rail.
- `crates/pocket/src/fleet.rs` (`Hosts.list`, links), `settings/ssh_hosts.rs` (Settings › Hosts rows, add form).
- `crates/pocket/src/modals/new_session.rs`, `new_session/picker.rs`, `new_session/machine.rs`: the composer and its machine pill.

## 1. Host terminals don't make phantom projects

**Bug:** `project::projects` (`crates/project/src/project.rs:15`) pushes the folder of every terminal no saved project holds. The rule was meant for this Mac's terminals, but host terminals (`//host/...` cwds) also arrive, including ones the host's own desktop started, so each of its worktrees shows as a project.

- Only cwds on this Mac add their folder as a project. A host cwd under no saved project adds nothing. A host cwd under a saved host project or its worktree still lands there.
- Tests: the bug case, a local orphan terminal still adds its folder, a host terminal under a saved host project still lands there.
- Update `CONTEXT.md` ("A terminal launched outside every project adds its folder as a project") to say *on this Mac*.

## 2. The Spaces model

New feature module `crates/pocket/src/spaces.rs` with `pub(crate) struct Spaces` (composed by `Desktop::new`) and plain functions:

- `space_of(project) -> Space` where `Space` is `Local` or `Host(id)`, from `hosts::split`.
- `in_space(projects, space)`: the projects of one space, order kept.
- `order(hosts)`: This Mac first, then hosts in Settings order.
- `waiting(agents_by_project, space)`: sessions waiting on the user in a space, for its badge.
- `step(order, current, ±1)` and `nth(order, i)` for swipe and ⌃1–⌃9.
- `twin(project, space, projects)`: the same-named project in another space (move it here from `new_session/machine.rs`).
- `colour(space, saved, position)`: the saved colour, else the palette's by position.

Persist in `store/prefs/sidebar.rs`: `space: Option<String>` (host id; `None` is This Mac) and `space_colours: HashMap<String, u32>`. A removed host's space falls back to This Mac.

Tests for each function, including: a removed host's saved space falls back to This Mac; ⌃9 past the last space does nothing; a project on two machines belongs to both spaces as two keys.

## 3. The sidebar shows one space

- **Space header** above PROJECTS: the space's tinted icon, name, link dot, address (hosts only), chevron. Click opens the space menu: Open terminal (on that machine), Reconnect (offline host), Host settings…, a row of colour swatches, then Remove host… (danger; opens the existing remove confirm). This Mac's menu: Open terminal, Hosts settings….
- **Switcher** at the aside's bottom, replacing the Settings row: one 32px button per space (icon, link dot for hosts, colour pip under the current one, amber badge with the waiting count on other spaces), then `+` (opens Settings › Hosts with the add form) and, at the right, Settings.
- `sidebar/sections` lists only the current space's projects; Pinned and groups keep working, filtered by space. The SESSIONS (Scratch) section shows only in This Mac's space.
- **Offline host space:** a card under PROJECTS ("devbox is offline", last seen, "agents there keep running", Reconnect) and the projects dimmed; working spinners stop.
- **Empty space:** "No projects on <host> yet" with Open folder… and Clone….
- **Switching:** click, ⌃1–⌃9, or a two-finger horizontal swipe over the aside (threshold like the prototype's 80px of delta); the list slides in from the side it came from (~220ms, ease-out). Respect reduce motion.
- The compact rail gets the same switcher buttons under its project switcher.
- The search field reads "Search all machines"; palette results on another machine show its name.
- Captures: `space-mac`, `space-devbox` (fixture host), `space-menu`, `space-offline`, `space-empty`.

## 4. The composer follows the space

- The machine pill shows the current space. Its menu ("Run on": This Mac, SSH hosts with dots, offline dimmed and not pickable, Add a host…) switches the space.
- Switching space picks `twin(...)` of the drafted project there, else the space's first project, else No project (This Mac only).
- The project menu lists the space's projects, then Open folder on <host>… and Clone from URL….
- An offline host blocks Send with a notice and Reconnect. The "not on this machine" warning stays only for a kept draft whose project left the space.
- Breadcrumb on the new-session page and session pages names the host when it isn't This Mac.
- Update the existing machine-pill tests; add: switching space carries the draft to the twin; switching to a space without one picks its first project.
- Captures: `form-space-devbox`, `form-machine` (menu), `form-offline`.

## 5. Open a folder or clone onto a host

- PROJECTS' folder-plus button opens a menu: Open folder… (This Mac: the macOS picker as today; a host: the host finder) and Clone from URL….
- Host finder: add the sidebar as an opener; choosing a folder saves `hosts::place(host, dir)` as a project, selects it in the composer, and flashes its row. A folder already a project can't be chosen.
- Clone from URL: "Clone into" shows a machine chip (defaults to the current space; menu of online machines). Choose… on a host opens the host finder in a *pick destination* mode ("Clone into", primary "Clone here"). The destination key is `hosts::place(host, path)`; the clone itself already runs on the host. Show progress ("Cloning on <host>") while it runs; when done, the project appears in its space, selected in the composer.
- Tests in `clone_project.rs` for the destination key on a host and the default folder under the host's home; in `host_finder/nav.rs` for the pick-destination footer.
- Captures: `add-menu`, `finder-open-host`, `clone-host`, `clone-host-progress`.

## 6. Settings › Hosts knows about spaces

- Each host row shows its space colour on its tile and an Open button (switches to its space) when connected.
- After an install finishes: "<host> is ready." with Open <host> and Done; the new space's switcher button pops in.
- The page's description adds "Each one is a space in the sidebar."
- The remove confirm says the space and its projects leave the sidebar and agents already running there keep going.
- Captures: `hosts-spaces`, `hosts-installed`.
