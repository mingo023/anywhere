# Settings (⌘,) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use /implement to execute this plan task-by-task.

**Goal:** A Settings page on ⌘, with General, Appearance, Keybindings and Worktrees sections, per `docs/research-settings.md` §5 steps 1–6.

**Architecture:** Preferences live in `store::Store` under new top-level `desktop.json` keys (`notifications`, `appearance`, `worktree`, plus `sounds.all`). Settings is a third `Screen` (like Inbox): it replaces the lead, column and page, and hides the session tree so browser/panels unmount. `pocket/src/settings.rs` owns `SettingsState` and pure helpers; each section is one file under `settings/`. pocketd reads `worktree.root` for its worktree folder fallback.

**Toolset (from `packages/desktop`):** `cargo build --workspace` · `cargo clippy --workspace --all-targets` · `cargo test --workspace` · one test: `cargo test -p <crate> <name>` · pocketd: `cd packages/pocketd && go test ./internal/registry/ ./internal/worktree/`

**Read first:** `docs/research-settings.md` (the spec), `docs/adr/0003-desktop-code-layout.md` (where code goes), `CLAUDE.md` (performance and test rules).

**Decisions:** ⌘, opens Settings; `ProjectSettings` stays as an action but unbound, row menu reads "Project settings…". Notifications sit inside General. Keybindings is read-only. Global worktree root is honoured by desktop and pocketd. Settings is not `Sessions`, so alerts treat it like Inbox. The per-project form stays a modal. No palette appearance entries.
