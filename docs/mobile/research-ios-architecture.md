# Research: iOS app architecture (SwiftUI, monorepo, mostly-SwiftPM)

Date: 2026-10-24. Scope: how to lay out, build, test and make fast the new native iOS app that replaces `packages/app`. Citations: `[n]` = Sources list at the end. `P path:L` = path in this repo. `PROBE` = a test I ran on this machine in `/tmp` (not in the repo).

## TL;DR

- **The toolchain blocks first, not the architecture.** This Mac has CLT Swift **5.9.2** with the macOS **14.2** SDK (`swift --version`, `xcrun --show-sdk-version`), no Xcode, and no XCTest. `swift test` fails with `error: XCTest not available` (PROBE).
  - Almost every library we want needs a newer `swift-tools-version`: swift-markdown 6.2, SwiftTerm 6.2, TCA 6.4, GRDB 6.1, Textual 6.0, Neon 6.0.
  - `swiftly` is installed (`~/.swiftly/bin/swiftly`) and offers Swift 6.3.x and 6.4.x, but no toolchain is installed.
  - **Step 0: install Swift 6.3+ via swiftly, update the CLT, and plan on installing Xcode 26/27.** Nothing can build the iOS app, extensions, signing or simulator without Xcode. "Most code on SwiftPM" cuts the Xcode dependency; it doesn't remove it.
- **Project:** a pure SwiftPM local package (`ios/Packages/AnywhereKit`) holds ~95% of the code. A thin app project is generated by **XcodeGen 2.46** (`project.yml`, `syncedFolder` sources, `.xcodeproj` gitignored). XcodeGen builds and runs with Swift 5.9 and needs no Xcode to generate. Tuist is overkill for 3 targets and needs Xcode to do anything useful.
- **State:** Observation (`@Observable`) in a **MV/store** style, no TCA. Use a few `@MainActor @Observable` stores fed by one connection actor.
  - TCA pulls swift-syntax macros and a tools-6.4 manifest, and costs compile time.
  - We already have a reducer-like source of truth: the daemon's message stream.
- **Navigation:** `NavigationStack(path:)` (iPhone) and `NavigationSplitView` (iPad), with a `Route: Hashable, Codable` enum. One `DeepLink` parser serves notifications, Live Activity `widgetURL`/`Link`, and the `anywhere://` scheme (already declared, `P packages/app/app.json` `"scheme": "anywhere"`).
- **WebSocket:** use **Network.framework `NWConnection` + `NWProtocolWebSocket`** inside an `actor`, not `URLSessionWebSocketTask`.
  - pocketd closes with private codes **4401 (unpaired)** and **4426 (version mismatch)** (`P packages/pocketd/internal/wsserver/wsserver.go:43-44`). NWProtocolWebSocket exposes those as `.privateCode`. URLSession's close-code handling is reported unreliable [9][10][11].
  - We dial plain `ws://` on the tailnet (`P packages/app/src/pairing.ts:61-65`). ATS applies only to URLSession and higher [12], so NWConnection side-steps ATS exceptions.
  - The iOS 26 `NetworkConnection` + `WebSocket` structured API is nicer [9], but it's iOS 26 only. Adopt it later.
- **Persistence:** GRDB (SQLite) for a cache of timelines and project lists. Plain files for blobs (diff/file text, rendered mermaid PNGs). Keychain via the Security framework (a 60-line wrapper; it compiles on macOS). No SwiftData: it's opaque and slow at scale [13], and our data is daemon-owned anyway.
- **Markdown:** parse with **swift-cmark (`gfm` branch) directly**, not swift-markdown.
  - Verified: swift-markdown only attaches `table`, `strikethrough` and `tasklist` (`CommonMarkConverter.swift:430-432`), with no autolink and no footnotes.
  - The desktop renders footnotes and GitHub alerts (`P packages/desktop/Cargo.toml:84`), so we need all of them.
  - PROBE: cmark-gfm with table, strikethrough, tasklist, autolink and `CMARK_OPT_FOOTNOTES` parsed **258 KB in 38 ms** (release, this Mac), with every node type present. It builds with Swift 5.9 today.
  - Our own AST feeds our own SwiftUI/TextKit renderer. Textual is not the core: it's iOS 18+, at 0.5.0, and parses via Foundation's `AttributedString` [3][4].
- **Terminal:** SwiftTerm (MIT, iOS 14+, Metal renderer optional, v1.99.1 on 2026-10-21) [5]. It's the only serious option. It needs tools 6.2, and the iOS view is UIKit, so it lives in an iOS-only module.
- **Syntax highlighting:** SwiftTreeSitter 0.10 + Neon (BSD-3), matching the desktop's tree-sitter grammars. Highlight only the visible range, off the main actor. Highlightr (JavaScriptCore, ~50 ms per 500 lines on an iPhone 6s [16]) can serve as a fallback for long-tail languages.
- **Mermaid:** BeautifulMermaid (`lukilabs/beautiful-mermaid-swift`, MIT, iOS 15+, native, 6 diagram types) [17], with an off-screen `WKWebView` + mermaid.js fallback for the other ~29 families the desktop's merman covers (`P docs/research-mermaid-rendering.md`). Cache by source hash.
- **Deployment target: iOS 18.0.**
  - iOS 26 is on 79% of devices (June 2026) [14], and iOS 27 shipped this fall (WWDC26 [15]).
  - iOS 18 gives `@Entry`, `ScrollPosition`, `onScrollGeometryChange`, `defaultScrollAnchor(_:for:)`, Live Activity broadcast push and Textual's floor.
  - Gate Liquid Glass and iOS 26 APIs with `#if compiler(>=6.2)` plus `if #available(iOS 26, *)` inside one `DesignSystem/Glass.swift`.

## 3. Modularization

### Principles

These mirror `docs/adr/0003-desktop-code-layout.md`: model crates hold logic and `pocket` holds views.

- **Model modules never import SwiftUI.** That makes them Linux-testable if `swift test` on macOS turns out to need Xcode.
  - Model modules: `Protocol`, `Client`, `Domain/*`, `MarkdownModel`, `DiffModel`, `Highlight`, `Persistence`.
- **Feature modules import SwiftUI and DesignSystem, plus their model modules.** They never import each other.
  - Cross-feature navigation goes through `Route` values in `AppRouting`, a tiny module of enums with no view types.
- **Interface/implementation split only where a seam is needed for tests.** That means the connection: `ClientInterface` holds a `DaemonClient` protocol plus message types; `Client` holds the NWConnection implementation.
  - No interface module per feature: at about 12 modules that's ceremony. SwiftPM recompiles only dependents, so a stable `Protocol` module keeps incremental builds cheap.
- **iOS-only code is `#if os(iOS)` inside a cross-platform module only when small.** Otherwise it goes in a separate target that only the Xcode app links: `TerminalUI` (SwiftTerm `TerminalView` is UIKit), `LiveActivityUI` (ActivityKit), `PushSupport`.
  - On macOS the cross-platform view modules use `NSViewRepresentable` only for previews and tests, or a `#if canImport(UIKit)` branch.
- One file per component. Tests sit beside each module as `Tests/<Module>Tests`, named as sentences (CLAUDE.md rule).

## 4. State management: Observation + stores (MV), not TCA

- **Observation tracks per property, per view.** A `body` re-runs only when a property it *read* changes [19][20]. That's the main lever for "every message redraws everything" problems, which mirror the desktop's `cx.notify()` issue in CLAUDE.md.
- **Store shape:**
  - `@MainActor @Observable final class SessionsStore { private(set) var order: [AgentID]; private(set) var byID: [AgentID: SessionModel] }`
  - `SessionModel` is itself `@Observable final class` (one per agent), so a status change on one card invalidates only that card.
  - Never expose one big `[Item]` that every row reads. That pattern invalidates every row [20].
- **Chat timeline:**
  - `TimelineStore` per agent holds `items: [TimelineRow]` of **immutable value rows** (`struct TimelineRow: Identifiable, Equatable { id: Seq; kind; renderKey }`).
  - The streaming tail is a separate `@Observable final class StreamingTail`, so only the last row re-renders per `agent.stream` frame (`P packages/protocol/src/messages.ts:170`, `epoch` + `item`).
- **Inputs from the daemon:**
  - `Client` (actor) decodes JSON off the main actor into `ServerMessage` enum values.
  - It yields over `AsyncStream`, and a single `@MainActor` `Router.apply(_ batch: [ServerMessage])` mutates stores.
  - Coalesce per run-loop tick (collect messages for ≤16 ms) so a burst of 500 `agent.timeline` items is one transaction.
- **Why not TCA:**
  - It's 1.23.3, with a tools-6.4 manifest and 7+ Point-Free deps. Macro-heavy (`@Reducer`, `@ObservableState`) means swift-syntax compile cost.
  - It also adds a second action layer on top of a protocol that is already action-shaped.
  - Its testability win (exhaustive `TestStore`) we get cheaply: stores are plain classes with `apply(ServerMessage)`, tested by feeding messages.
- **Pure logic (no `@Observable`) for anything non-trivial:** ordering (`P packages/app/src/order.ts` semantics), diff hunking, markdown block split. Write free functions over values, unit tested. Same rule as the desktop's "decisions live in state methods or free functions".

## 5. Navigation and deep links

- `enum Route: Hashable, Codable { case project(ProjectPath), worktree(WorktreePath), local(LocalID), session(AgentID), diff(WorktreePath, file: String?), file(WorktreePath, String), pr(Repo, Int), terminal(TerminalID) }`
- `@Observable final class Navigator { var path: [Route]; var sidebarSelection: Route? }`
  - iPhone: `NavigationStack(path: $nav.path)` with `.navigationDestination(for: Route.self)`.
  - iPad: `NavigationSplitView` (sidebar = workspace tree, content = sessions, detail = chat/diff).
- `DeepLink.parse(URL) -> [Route]` handles `anywhere://session/<agentId>?host=<hostId>`. One function is used by:
  - `onOpenURL` (scheme and Live Activity `widgetURL` / `Link`)
  - `UNUserNotificationCenterDelegate.didReceive` (`userInfo["link"]`)
  - `NSUserActivity` (Handoff from the desktop)
- Unit-test it in `AppRouting` (pure).
- Persist `path` as `Codable` data in `SceneStorage` for state restoration.

## 6. Networking: WebSocket client under Swift 6 strict concurrency

```swift
public actor DaemonConnection: DaemonClient {
  private var conn: NWConnection?
  private var pending: [String: CheckedContinuation<ServerMessage, Error>] = [:]
  private let events: AsyncStream<ConnectionEvent>.Continuation  // .connected, .message(ServerMessage), .closed(CloseReason)
  public nonisolated let stream: AsyncStream<ConnectionEvent>
  public func request(_ m: ClientMessage) async throws -> ServerMessage   // id-correlated, timeout via Task.sleep race
  public func send(_ m: ClientMessage) async throws                      // fire-and-forget
}
```

- **Transport:** `NWParameters.tcp` (or `.tls` for non-tailnet `wss`, per `wsURL` `P packages/app/src/pairing.ts:61-65`), with `NWProtocolWebSocket.Options()` inserted at index 0 of `applicationProtocols`. Set `autoReplyPing = true` and `maximumMessageSize` large enough for 500-item timelines.
  - Compiles on macOS 14 SDK (PROBE).
  - Read the close code from `NWProtocolWebSocket.Metadata.closeCode`: `.privateCode(4401)` means unpaired (go to pairing UI), `.privateCode(4426)` means version mismatch.
  - URLSession's `closeCode` is reported as `invalid` in some states [11], and its custom close codes are unreliable [10].
- **Receive loop:** `conn.receiveMessage` callback → decode on a dedicated serial `DispatchQueue` (the NWConnection queue) → `events.yield`. Because `NWConnection` isn't `Sendable`, keep it confined to the actor. Wrap callbacks with `withCheckedThrowingContinuation`, or use `nonisolated(unsafe)` only inside the queue closure.
- **Backpressure:** `AsyncStream(bufferingPolicy: .unbounded)` for protocol messages (none may be dropped, since `seq`/`epoch` matter). Terminal output, if it later rides binary frames, uses its own stream with `.bufferingNewest(n)` per terminal plus a resync request.
- **Reconnect:**
  - Exponential backoff 0.25 s → 8 s with full jitter, reset on `hello.ok`.
  - `NWPathMonitor` path change → immediate retry.
  - `scenePhase == .active` → retry now. Background → close cleanly after 30 s; iOS will suspend us anyway, and Live Activities and push carry state while backgrounded.
  - On reconnect: `hello` (with `protocol: {min:3,max:3}`, `caps`, `P packages/protocol/src/constants.ts`), then resubscribe `agent.view`, then `agent.timeline` with `sinceSeq` per open chat.
- **JSON:**
  - Use `JSONDecoder` with a hand-written `init(from:)` that switches on `type` for the `ClientMessage`/`ServerMessage` unions. Effect's `Schema.Union` maps to Swift `enum` with associated structs.
  - Keep `Protocol` generated or hand-mirrored from `packages/protocol/src/*.ts`, with golden JSON fixtures shared from the TS tests.
  - Decode off-main always. For 1000+-file git status payloads, decode into compact structs (no `AnyCodable`).
- **Swift 6 settings:** `swiftLanguageModes: [.v6]` for all package targets, so strict concurrency is on by default. `@MainActor` on stores and views. Model types are `Sendable` structs.
- **Local network privacy:** the app needs `NSLocalNetworkUsageDescription` for LAN or loopback hosts. Tailscale 100.x goes over the Tailscale VPN interface; spike whether the prompt triggers. NWConnection on a device can fail silently when permission is missing [12, thread 769984].

## 7. Persistence, cache, keychain

- **GRDB 7.11 (MIT)**, one DB in the App Group container so the Notification Service Extension and widget can read the cache.
  - Tables: `host`, `project`, `worktree`, `local`, `agent_summary`, `timeline_item(agent_id, seq, epoch, json BLOB)`, `kv`.
  - WAL mode. `ValueObservation` is not needed; stores are the live source and the DB is cold-start cache only.
  - SQLiteData (Point-Free, on GRDB) is an option if we later want `@FetchAll` in views [13]. We don't need it.
- **Files** (`Caches/` + content hash): file previews, diff text, rendered mermaid PNG/SVG, highlighted-token caches.
- **SwiftData: no.** It's opaque performance [13], `@Model` macros are tied to SwiftUI lifecycle, and we cache daemon-owned data, not user documents.
- **Keychain:** a 60-line `Keychain` struct over `SecItemAdd`/`SecItemCopyMatching` with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` and `kSecAttrAccessGroup` = App Group keychain group, so the extension can read the device token for pushes. It replaces `expo-secure-store` (`P packages/app/src/keychain.ts`, `credentials.ts`). The Security framework compiles on macOS, so it can be tested on macOS (the keychain needs a signed host on iOS only).

## 8. Dependency injection without frameworks

- Use **constructor injection plus one `AppEnvironment` struct** built in `AppShell`: `struct AppEnvironment { var client: any DaemonClient; var db: AppDatabase; var keychain: Keychain; var clock: any Clock<Duration>; var now: @Sendable () -> Date }`.
- Pass stores into views with SwiftUI's `.environment(store)`, the Observation-native, type-keyed environment. Read them with `@Environment(SessionsStore.self)`.
- Use `@Entry` for small values (theme, feature flags).
- Tests build stores with a `FakeDaemon: DaemonClient` actor. It's a real implementation that replays fixture JSON, not a mock framework.

  - On macOS it may need Xcode's runner (§1). Ensure `Protocol`, `Domain`, `MarkdownModel`, `DiffModel`, `Stores` (no SwiftUI) also pass on Linux in Docker as the fallback.

  - Protocol golden fixtures (decode and re-encode equality vs TS).
  - Store `apply` sequences: reconnect plus `sinceSeq` merge, `epoch` reset.

  - Markdown AST → block model, with fixtures copied from the desktop's markdown tests.

## 11. Deployment target and availability isolation

- **Minimum iOS 18.0.** Reasons:
  - iOS 26 is at 79% of all compatible iPhones (June 2026) [14], and iOS 18 still covers the long tail.
  - Live Activity broadcast channels are iOS 18 (push-to-start is 17.2, unreliable on 17.x) [24].
  - iOS 18 has `ScrollPosition`, `onScrollGeometryChange`, `defaultScrollAnchor(_:for:)`, `@Entry`, `Tab` API and `MeshGradient`.
  - Textual (if used for small text) requires iOS 18 (`Package.swift` `.iOS(.v18)`).
- **iOS 26 and 27 only** (Liquid Glass `glassEffect`, `GlassEffectContainer`, iOS 26 `NetworkConnection`, iOS 27 `reorderable()` [15]): only in `DesignSystem/Glass.swift`, `Client/NetworkConnectionTransport.swift`, and similar files.
  ```swift
  #if compiler(>=6.2)          // SDK 26 present (Xcode 26 = Swift 6.2)
  if #available(iOS 26, macOS 26, *) { content.glassEffect(.regular, in: shape) } else { content.background(.ultraThinMaterial, in: shape) }
  #else
  content.background(.ultraThinMaterial, in: shape)
  #endif
  ```
  Local SwiftPM builds (SDK 14.2) take the `#else` branch. Xcode builds get both.
- **Package platforms:** `.iOS(.v18), .macOS(.v14)`. macOS 14 is required for Observation and matches the local SDK. Bump macOS to `.v15` once the CLT is updated. It exists only for local builds and tests; the macOS app is Rust.

## 12. Libraries

### Terminal: SwiftTerm, the only real choice
- MIT, by Miguel de Icaza. Tools 6.2, `.iOS(.v14)`, `.macOS(.v11)`. v1.99.1 on 2026-10-21, actively pushed.
- iOS UIKit `TerminalView` and macOS AppKit view. Optional Metal renderer (macOS, iOS, visionOS).
- Supports TrueColor, mouse, bidi, Sixel, iTerm2 and Kitty graphics, and grapheme clusters. Used in Secure Shellfish, La Terminal and CodeEdit [5].
- Feed remote bytes with `terminal.feed(byteArray:)`. Keystrokes come back through `TerminalViewDelegate.send(source:data:)`, and resizes through `sizeChanged(source:newCols:newRows:)`, which map to daemon terminal input/resize messages.
- **The protocol has no terminal messages yet:** `P packages/protocol/src/messages.ts` lists only `agent.*`, `project.*`, `local.*`, `pair.*`, `automation.*`. The desktop uses pocketd's own channel.
  - Terminal I/O needs new messages. Prefer **binary WS frames** (`NWProtocolWebSocket.Opcode.binary`) with a small header (terminalID, seq) to avoid base64 and JSON on the hot path.
- Perf: no published iOS numbers. The README says "seems pretty fast" [5]. Benchmark the Metal vs CoreGraphics renderer with `cat` of a 10 MB log on device.
- Module: `TerminalUI` (iOS only, links SwiftTerm). The headless `Terminal` engine also builds on macOS for unit tests of our glue.

| apple/swift-markdown 0.9.0 (Apache-2.0, 2026-09-21) | Tables, strikethrough, task lists. **No autolink, no footnotes** (`CommonMarkConverter.swift:430-432` attaches only those three) | Nice immutable value AST, `MarkupVisitor` | Skip (missing GFM; tools 6.2) |
| MarkdownUI (gonzalezreal) | Maintenance mode [3] | — | Skip |
| Textual 0.5.0 (MIT, iOS 18+/macOS 15+) | Uses Foundation `AttributedString` markdown parsing [4]. Has text selection, math (`swiftui-math`), syntax highlighting, animated images. Footnotes and task lists not mentioned | Young (0.x) | Maybe borrow ideas or use it for math; not the core |
| Down (cmark wrapper, renders via HTML/NSAttributedString) | CommonMark only, stale | — | Skip |

Renderer design:
- Blocks map to SwiftUI views: `Heading`, `Paragraph`, `List`/`TaskList`, `Table` (horizontal `ScrollView` + `Grid`), `CodeBlock` (CodeView + highlight), `BlockQuote`/`Alert`, `ThematicBreak`, `Image`, `FootnoteDefinitions`, `Mermaid`.
- Inlines become one `AttributedString` per paragraph, so a paragraph is a single `Text`. That's fast, and selection is possible via `.textSelection(.enabled)`, whole-block only.
- For precise selection in long assistant messages, use a TextKit 2 `UITextView` mode.
- Footnote numbering must be computed by us; cmark doesn't store it in the AST [25].

### Mermaid
- **BeautifulMermaid 1.0.4** (MIT, iOS 15+, tools 5.9, native, ELK layout via `elk-swift`) renders flowchart, state, sequence, class, ER and XY charts to UIImage, SVG or SwiftUI view [17]. Render off-main and cache the PNG by `sha256(source + theme)`. Show the code block as the placeholder, and source plus the error on failure. Same UX as the desktop (`P docs/research-mermaid-rendering.md` TL;DR).
- **Fallback:** one shared off-screen `WKWebView` with bundled `mermaid.min.js` for other diagram types. Render to SVG string, then rasterize with `WKWebView.takeSnapshot`, queued serially.
- `swift-mermaid` (Australware, 0.1.0): flowchart, sequence and pie only. Watch it.
- merman (the desktop's Rust renderer) would need a Rust static lib for `aarch64-apple-ios` plus C ABI. That's possible later for exact parity, but needs Xcode's iOS SDK to build.

## 14. Risks and open questions

1. **Can `swift test` run on macOS without Xcode** using a swiftly 6.3 toolchain? Unverified (§1). It decides whether local TDD runs natively or in Docker/Linux. Spike: `swiftly install 6.3.3 && swift test` in `/tmp/swprobe` (needs user approval to install).
2. **swift.org 6.x compiler against SDK 14.2 swiftinterfaces:** usually fine, but SwiftUI macro plugins (`#Preview`, `@Entry`) come from the SDK/toolchain pairing. Updating the CLT is the cleaner fix.
3. **Protocol gaps:** git status/log/branches, GitHub, diff, file content and terminal I/O have no phone messages today (`P packages/protocol/src/messages.ts`). The architecture assumes new request/response messages plus binary terminal frames. Other research docs own that.
4. **APNs and Live Activity push** need a sender. pocketd runs on the user's Mac and holds no APNs key. Decide whether that's a relay service or a user-provided key; that decides what the NotifyService extension decrypts.
5. **Neon has no tagged release since 2024.** Pin a commit.
6. **LazyVStack chat memory:** no recycling. Enforce windowing and measure on an iPhone 12-class device.
