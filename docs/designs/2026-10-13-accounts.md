# Design: several Claude Code and Codex accounts

Date: 2026-10-13. Base: `3ecb6b7`. `pd` = `packages/pocketd`, `pk` = `packages/desktop/crates/pocket/src`, `d` = `packages/desktop/crates`.
UI reference: the "Ledger" prototype (`.ui-review/prototypes/accounts.html`, deleted once promoted).

## 1. Decisions

1. v1 is an account list per host, a default account, a session label and usage meters. No automatic switching when an account hits its limit.
2. A new agent starts on its provider's default account on that host, picked with a radio on the Accounts page; a signed-out account can't be picked. The composer has no account chip. Running agents follow the default (decision 14).
3. Only accounts that Anywhere manages are listed. Each has its own folder: `~/.anywhere/accounts/<provider>/<id>/`, the same for dev and release builds, always an absolute literal path.
4. The built-in login (`~/.claude`, `~/.codex`) is the account `builtin`. It sets no env var and can't be removed, only signed out.
5. An account has its own login and identity, and shares the user's config. A session's account is read from its process env (`CLAUDE_CONFIG_DIR` / `CODEX_HOME`), so restore keeps it.
   - A managed account's folder links to the built-in one for what the user configured (Claude: settings, CLAUDE.md, skills, commands, agents, hooks, plugins, rules, output styles, keybindings, projects; Codex: config.toml, AGENTS.md, skills, prompts, hooks.json, sessions). A conversation can therefore resume on another account. A real history folder the account already had is merged into the user's first.
   - Credentials are never linked. For Claude, `.claude.json` takes the user's `mcpServers`, `hasCompletedOnboarding` and per-project entries, which include folder trust, so a resume doesn't stop at a trust dialog. Its login keys stay the account's.
   - A fork starts on its source session's account, then follows the default like any agent.
6. Each host's pocketd has its own accounts, and sign-in runs on that host.
7. Signing in runs in a pocket terminal that the desktop attaches to but never shows as a tab. A panel under the provider's accounts shows the link and Codex's one-time code read from its screen, a field that types Claude's code back into it, its output on demand, and Cancel:
   - Claude: `CLAUDE_CONFIG_DIR=<dir> claude auth login`.
   - Codex: `CODEX_HOME=<dir> codex login --device-auth`.
   - When the terminal exits, pocketd reads the identity. With none, it deletes the folder.
   - The label defaults to the email. The same email can't be added twice for one provider.
8. For managed accounts only, the shell script unsets these just before the agent runs, after the login shell has read the user's rc files: `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `OPENAI_API_KEY`, `CODEX_API_KEY`, `CODEX_ACCESS_TOKEN`.
9. Usage meters (5-hour and weekly):
   - pocketd fetches and caches them when the desktop asks: once on connect, every 5 minutes while it is open, and from the ↻ button.
   - Access tokens are read-only and never refreshed. When a token has expired, the last values are kept and shown as stale ("As of HH:MM").
   - Endpoints:
     - Claude: `GET https://api.anthropic.com/api/oauth/usage` with `anthropic-beta: oauth-2025-04-20`. It reads `five_hour` and `seven_day` `{utilization, resets_at}`.
     - Codex: `GET https://chatgpt.com/backend-api/wham/usage` with `ChatGPT-Account-Id`. It reads `rate_limit.primary_window` and `rate_limit.secondary_window` `{used_percent, reset_at}`, plus `plan_type`.
10. "Sign out" runs the CLI's own logout with the account's env and keeps the folder and history. "Remove" signs out, then deletes the folder, which holds the login and nothing else the user would miss: history lives in the built-in folder. Remove is refused while a session on that account is running.
11. The phone has no picker. `LaunchSpec.account` is optional. pocketd resolves it in this order: the spec's account, then the provider's default account, then the built-in one. The desktop sends none for a new agent, and the source's account for a fork. Once the agent has a conversation it follows the default whatever it started on.
12. Plain agent tabs (`agent_op`) start on the built-in account and follow the default like any agent.
13. Running agents follow the default (`Daemon.Follow`):
   - It runs when the default changes, when any agent's turn ends or is stopped, and when a restore settles.
   - An agent moves only when it is attached, idle (or done without a failure), on another account than the default, has a conversation with a transcript, and the default is signed in. A busy agent moves when its turn ends.
   - It moves by resuming the same conversation on the new account in the same terminal: the agent keeps its id and its terminal, the screen is reset and no exit is reported.
   - The resume argv is the restore's, so `Full` access comes back as `ask` with a notice, and `restore.resumeAgents` off disables following.
   - A prompt typed in the instant between the check and the restart is lost.
14. Out of scope: renaming the home folder to `~/.anywhere`, Codex keyring storage, `token_count` meter updates, failover.

## 2. Wire

### WS (`pd/internal/proto`, `packages/protocol`)

- New cap `accounts.v1`. Older servers reject unknown keys, so the desktop sends `spec.account` only when that host's pocketd has listed the account through the `accounts` op, which older ones don't answer.
- `LaunchSpec.Account string \`json:"account,omitempty"\``: either `builtin` or an account id.
- `decodeSpec` allows the `account` key.
- An unknown id fails the create with code `unknown_account`.
- `AgentSummary.Account string \`json:"account,omitempty"\``: the account id, or empty for the built-in one.
- New golden file: `agent_create_account.json`.

### ops (`pd/internal/ops`, all verbs `Own` in `peer.Needs`)

`key` is the provider, `id` the account id (`builtin` for the built-in login), `text` a label. Each verb except `accounts.signin` replies with `accounts`, or an error.

| op | in | out |
|---|---|---|
| `accounts` | — | `{ev:"accounts", accounts:[Account]}` |
| `accounts.usage` | `id`; empty means all | `accounts`, after fetching |
| `accounts.signin` | `key`, `id`; empty `id` adds an account | `{ev:"spawned", id: terminalId, text: accountId}` |
| `accounts.rename` | `key`, `id`, `text` | `accounts` |
| `accounts.default` | `key`, `id`; a signed-out managed account is refused | `accounts`, then restarts the agents that follow (decision 13) |
| `accounts.signout` | `key`, `id` | `accounts` |
| `accounts.remove` | `key`, `id`; also dismisses a failed sign-in | `accounts`, or an error |

```go
type Account struct {
    ID       string // "builtin" or the folder's name
    Provider string
    Label    string // empty shows Email
    Email    string
    Plan     string // "Max", "Pro", "Plus", …
    SignedIn bool
    Default  bool   // what new agents start on, for its provider
    Running  int
    Usage    *Usage
    Pending  bool   // signing in; Error is set if that failed
    Error    string
}
type Usage struct{ Session, Week *Window; At int64; Stale bool }
type Window struct{ Percent float64; ResetsAt int64 }
```

## 3. pocketd

- `pd/internal/accounts`: `Store{Root, Home, Secret}`; `Secret` reads a Keychain item on macOS. The index lives at `<Root>/accounts.json` as `{accounts:[{id, provider, label, email, plan}], defaults:{provider:id}}`.
- It provides:
  - `List` and `Resolve(provider, id)`.
  - `Env(a)`, which returns the env var to set.
  - `Of(provider, env)`, which maps a process env to an account id.
  - `Add`, `Finish`, `Dismiss`, `Rename`, `SetDefault` and `Remove`. Signing out runs in `launch`, which owns finding the CLI.
  - `Share(provider, id)`, which links a managed account to the user's config (decision 5). `launch.account` calls it before every launch and resume; `Follow` calls it for the account an agent leaves.
  - Identity readers:
    - Claude: `<dir>/.claude.json` `oauthAccount.emailAddress` and `organizationType`.
    - Codex: the `<dir>/auth.json` `id_token` claims `email` and `chatgpt_plan_type`.
  - Signed in:
    - Claude: the Keychain item `Claude Code-credentials[-sha256(dir)[:8]]` on macOS, else `<dir>/.credentials.json`.
    - Codex: `auth.json` has tokens.
  - The usage fetcher.
- `launch`:
  - `create` resolves the account and adds its env var to `env` before trust, spawn and naming.
  - `Wrap` takes the vars to unset.
  - `resumeCmd` adds the saved account's env, from `state.Terminal.Account`.
- `terminal`: `Terminal.Replace(cmd, args, env)` swaps the process under a live terminal: same id and subscribers, screen reset, old session ended, no exit event.
- `daemon`:
  - `Follow(provider)` and `move` (decision 13). A move registers a `hint{moved}` so the agent refuses prompts until the new process settles, and `endAgent` keeps the agent listed meanwhile.
  - `startAgent` sets `Agent.Account` from `accounts.Of(pr.env)`. `pr.save` writes it to `state.Terminal`. `claude auth …` isn't detected as an agent, so a sign-in terminal stays a plain terminal.

## 4. Desktop

- `d/daemon`: account ops, using `request_to` with the host's `Endpoint`.
- `pk/accounts.rs`: the `Accounts` state struct (each host's list, usage checks, sign-in terminals), shared by the page and the sidebar.
- `pk/settings/accounts.rs`: the Ledger page, with a nav entry under Agents. Host groups each hold a provider caption row, with its own "Add account", and account rows with meters and a ⋯ menu.
  - Each account row has a radio for the provider's default; a signed-out account can't be picked.
  - Add runs the sign-in in a hidden terminal and shows its panel under the provider; one per provider and host at a time. Cancel drops the account it was adding.
  - The built-in login can't be renamed.
  - Rename is an inline field.
  - Remove and Sign out each confirm first.
- Session rows: show the account label when that provider has more than one account on the host.
