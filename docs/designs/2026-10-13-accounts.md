# Design: several Claude Code and Codex accounts

Date: 2026-10-13. Base: `3ecb6b7`. `pd` = `packages/pocketd`, `pk` = `packages/desktop/crates/pocket/src`, `d` = `packages/desktop/crates`.
UI reference: the "Ledger" prototype (`.ui-review/prototypes/accounts.html`, deleted once promoted).
Revised 2026-10-22 (switching): running agents no longer follow the default. A chat switches account by hand, any session Pocket started switches at its limit, and a project can pick its accounts. Prototypes: `.ui-review/prototypes/account-switch.html` and `account-settings.html`.

## 1. Decisions

1. An account list per host, a default account, a session label and usage meters; a chat's account chip to switch by hand (decision 13), switching at a limit (decision 15), and a project's own accounts (decision 16).
2. A new agent starts on an account picked in this order: the launch's, the project's, the provider's default on that host (a radio on the Accounts page), the built-in login. A signed-out one gives way to the next in that order; one at its limit gives way to the signed-in account with the most left, while switching at a limit is on. A signed-out account can't be made the default. The new session composer has no account chip. A running agent keeps its account: a new default applies to new agents only.
3. Only accounts that Anywhere manages are listed. Each has its own folder: `~/.anywhere/accounts/<provider>/<id>/`, the same for dev and release builds, always an absolute literal path.
4. The built-in login (`~/.claude`, `~/.codex`) is the account `builtin`. It sets no env var and can't be removed, only signed out.
5. An account has its own login and identity, and shares the user's config. A session's account is read from its process env (`CLAUDE_CONFIG_DIR` / `CODEX_HOME`), so restore keeps it.
   - A managed account's folder links to the built-in one for what the user configured (Claude: settings, CLAUDE.md, skills, commands, agents, hooks, plugins, rules, output styles, keybindings, projects; Codex: config.toml, AGENTS.md, skills, prompts, hooks.json, sessions). A conversation can therefore resume on another account. A real history folder the account already had is merged into the user's first.
   - Credentials are never linked. For Claude, `.claude.json` takes the user's `mcpServers`, `hasCompletedOnboarding` and per-project entries, which include folder trust, so a resume doesn't stop at a trust dialog. Its login keys stay the account's.
   - A fork starts on its source session's account.
6. Each host's pocketd has its own accounts, and sign-in runs on that host.
7. Signing in runs in a pocket terminal that the desktop attaches to but never shows as a tab. A panel under the provider's accounts shows the link and Codex's one-time code read from its screen, a field that types Claude's code back into it, its output on demand, and Cancel:
   - Claude: `CLAUDE_CONFIG_DIR=<dir> claude auth login`.
   - Codex: `CODEX_HOME=<dir> codex login --device-auth`.
   - When the terminal exits, pocketd reads the identity. With none, it deletes the folder.
   - The label defaults to the email. The same email can't be added twice for one provider.
8. For managed accounts only, the shell script unsets these just before the agent runs, after the login shell has read the user's rc files: `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `OPENAI_API_KEY`, `CODEX_API_KEY`, `CODEX_ACCESS_TOKEN`.
9. Usage meters (5-hour and weekly):
   - pocketd fetches and caches them when the desktop asks: once on connect, every 5 minutes while it is open, and from the ↻ button.
   - Access tokens are read-only and never refreshed. When a token has expired, the last values are kept and shown as stale ("As of HH:MM").
   - Endpoints:
     - Claude: `GET https://api.anthropic.com/api/oauth/usage` with `anthropic-beta: oauth-2025-04-20`. It reads `five_hour` and `seven_day` `{utilization, resets_at}`.
     - Codex: `GET https://chatgpt.com/backend-api/wham/usage` with `ChatGPT-Account-Id`. It reads `rate_limit.primary_window` and `rate_limit.secondary_window` `{used_percent, reset_at}`, plus `plan_type`.
10. "Sign out" runs the CLI's own logout with the account's env and keeps the folder and history. "Remove" signs out, then deletes the folder, which holds the login and nothing else the user would miss: history lives in the built-in folder. Remove is refused while a session on that account is running.
11. The phone has no picker, but pocketd resolves a phone's launch the same way (decision 2), so a project's accounts and switching at a limit apply to it. `LaunchSpec.account` is optional. The desktop sends none for a new agent, and the source's account for a fork.
12. Plain agent tabs (`agent_op`, a TUI opened by +) start as decision 2 says and switch at a limit, but have no chip. The desktop names the tab's provider in the spawn op (`agent`, with `argv`); pocketd wraps `argv` as a launch does, on the account `Store.Pick` gives the tab's project, and marks it the desktop's, so it also resumes after a pocketd restart. An agent the user typed into a shell is never switched.
13. A chat switches account by hand (`Daemon.Switch`, op `accounts.switch`):
   - The chip sits beside the branch under the composer: the account's name, a mini meter and the fuller of its 5-hour and weekly use (amber from 80%, red at 100%). It shows only while the provider has another account on that host, and pocketd there is new enough to switch (it reports `autoSwitch`).
   - It opens a two-page popover. Usage: the account in use, its 5-hour and weekly limits with what's left and when they reset, ↻, and "Switch account · N more ›". Switch account: every account with its use; ✓ on the current one. The pages slide; Esc on the second goes back, on the first closes.
   - An account at its limit can be picked; a signed-out one can't.
   - A switch picked mid-turn waits for the turn to end. The chip and the session row show the new account at once (`AgentSummary.Switching`); nothing else says so.
   - It moves by resuming the same conversation on the new account in the same terminal: the agent keeps its id and its terminal, the screen is reset and no exit is reported. Unlike a restart, Full access stays Full (`state.Terminal.KeepAccess`), with no notice.
   - An agent moves only when it is attached, between turns (a failed turn counts), and has a conversation with a transcript. A chat that hasn't had a turn yet keeps its switch until its first one ends. A switch that can't resume is dropped.
14. Out of scope: renaming the home folder to `~/.anywhere`, Codex keyring storage, `token_count` meter updates.
15. Switching at a limit (`Daemon.limitHit`), a per-host toggle on the Accounts page, on by default, stored in pocketd's `accounts.json` so it works with the desktop closed:
   - It starts on the agent's own limit error, as it happens: Claude's transcript line `error:"rate_limit"`, Codex's live `turn/completed` with `codexErrorInfo` `usageLimitExceeded`.
   - pocketd reads every account's usage, then moves the agent to the signed-in account of the same provider with the lowest peak use that isn't at a limit (a limit past its reset time isn't one; an account never read comes last), and sends it "continue" once it settles: the resumed conversation holds the stopped turn, whether a prompt, a task notification or a goal started it (a TUI may not take it).
   - It doesn't return when the old account resets. With every account at a limit it does nothing, and the agent's own error stands. It says nothing beyond the chip and the session row.
16. A project picks an account per provider in its Project settings (Settings › Projects, renamed from Projects & Worktrees), shown only while the provider has another account on the project's host; "Default" leaves it to decision 2. The project list names the picks after the path. It lives in `RepoConfig.accounts`, which reaches pocketd through `desktop.json` (`repos[path].accounts`), synced to a remote host with its registry.
17. An account that signs in as the same person (email) as one listed before it, as when the built-in login is later signed in outside Anywhere as a managed account's person, is its duplicate (`Account.same`, the earlier one's id). The Accounts page hides it while no session runs on it and it isn't the default, and tags it "Same as Built-in" (else "Duplicate") when shown; it keeps its login, so it is back once the earlier one signs in as someone else. It is no choice: not in a chat's switch list unless the chat is on it, not in a project's picker unless picked, not counted to show the chip or "New agents", and never switched to at a limit.

## 2. Wire

### WS (`pd/internal/proto`, `packages/protocol`)

- New cap `accounts.v1`. Older servers reject unknown keys, so the desktop sends `spec.account` only when that host's pocketd has listed the account through the `accounts` op, which older ones don't answer.
- `LaunchSpec.Account string \`json:"account,omitempty"\``: either `builtin` or an account id.
- `decodeSpec` allows the `account` key.
- An unknown id fails the create with code `unknown_account`.
- `AgentSummary.Account string \`json:"account,omitempty"\``: the account id, or empty for the built-in one.
- `AgentSummary.Switching string \`json:"switching,omitempty"\``: the account it moves to once its turn ends, `builtin` for the built-in one.
- New golden files: `agent_create_account.json`, `agent_update_switching.json`.

### ops (`pd/internal/ops`, all verbs `Own` in `peer.Needs`)

`key` is the provider, `id` the account id (`builtin` for the built-in login), `text` a label. Each verb except `accounts.signin` replies with `accounts`, or an error. An `accounts` reply carries `autoSwitch`, whether that host switches at a limit.

| op | in | out |
|---|---|---|
| `accounts` | — | `{ev:"accounts", accounts:[Account]}` |
| `accounts.usage` | `id`; empty means all | `accounts`, after fetching |
| `accounts.signin` | `key`, `id`; empty `id` adds an account | `{ev:"spawned", id: terminalId, text: accountId}` |
| `accounts.rename` | `key`, `id`, `text` | `accounts` |
| `accounts.default` | `key`, `id`; a signed-out managed account is refused | `accounts` |
| `accounts.switch` | `key`, `id`, `text` the agent; a signed-out account, or an agent the user typed, is refused | `accounts` (decision 13) |
| `accounts.autoswitch` | `text` `on` or `off` | `accounts` |
| `accounts.signout` | `key`, `id` | `accounts` |
| `accounts.remove` | `key`, `id`; also dismisses a failed sign-in | `accounts`, or an error |

```go
type Account struct {
    ID       string // "builtin" or the folder's name
    Provider string
    Label    string // empty shows Email
    Email    string
    Plan     string // "Max", "Pro", "Plus", …
    SignedIn bool
    Default  bool   // what new agents start on, for its provider
    Running  int
    Usage    *Usage
    Pending  bool   // signing in; Error is set if that failed
    Error    string
    Same     string // the account listed before it signed in as the same email (decision 17)
}
type Usage struct{ Session, Week *Window; At int64; Stale bool }
type Window struct{ Percent float64; ResetsAt int64 }
```

## 3. pocketd

- `pd/internal/accounts`: `Store{Root, Home, Secret}`; `Secret` reads a Keychain item on macOS. The index lives at `<Root>/accounts.json` as `{accounts:[{id, provider, label, email, plan}], defaults:{provider:id}, autoSwitch?}`.
- It provides:
  - `List` and `Resolve(provider, id)`.
  - `Pick(provider, id, prefer)`, a new session's account (decision 2), and `Best(provider, except)`, the one with the most left; `AutoSwitch` and `SetAutoSwitch`.
  - `Env(a)`, which returns the env var to set.
  - `Of(provider, env)`, which maps a process env to an account id.
  - `Add`, `Finish`, `Dismiss`, `Rename`, `SetDefault` and `Remove`. Signing out runs in `launch`, which owns finding the CLI.
  - `Share(provider, id)`, which links a managed account to the user's config (decision 5). `launch.account` calls it before every launch and resume; `move` calls it for the account an agent leaves.
  - Identity readers:
    - Claude: `<dir>/.claude.json` `oauthAccount.emailAddress` and `organizationType`.
    - Codex: the `<dir>/auth.json` `id_token` claims `email` and `chatgpt_plan_type`.
  - Signed in:
    - Claude: the Keychain item `Claude Code-credentials[-sha256(dir)[:8]]` on macOS, else `<dir>/.credentials.json`.
    - Codex: `auth.json` has tokens.
  - The usage fetcher.
- `launch`:
  - `create` picks the account, with the project's from the registry, and adds its env var to `env` before trust, spawn and naming.
  - `Wrap` takes the vars to unset.
  - `resumeCmd` adds the saved account's env, from `state.Terminal.Account`.
- `terminal`: `Terminal.Replace(cmd, args, env)` swaps the process under a live terminal: same id and subscribers, screen reset, old session ended, no exit event.
- `daemon`:
  - `Switch(agent, account)`, `limitHit` and `move` (decisions 13 and 15). The account a switch waits for is `Agent.Switching`; a turn's end, a stop and a settled restore apply it. A move registers a `hint{moved, resend}` so the agent refuses prompts until the new process settles, and `endAgent` keeps the agent listed meanwhile.
  - `startAgent` sets `Agent.Account` from `accounts.Of(pr.env)`. `pr.save` writes it to `state.Terminal`. `claude auth …` isn't detected as an agent, so a sign-in terminal stays a plain terminal.

## 4. Desktop

- `d/daemon`: account ops, using `request_to` with the host's `Endpoint`.
- `pk/accounts.rs`: the `Accounts` state struct (each host's list, usage checks, sign-in terminals), shared by the page and the sidebar.
- `pk/settings/accounts.rs`: the Ledger page, with a nav entry under Agents. Host groups each hold the "Switch accounts at a limit" toggle (dimmed while no agent has a second account there), a provider caption row, with its own "Add account", and account rows with meters and a ⋯ menu.
  - Each account row has a radio for the provider's default; a signed-out account can't be picked.
  - Add runs the sign-in in a hidden terminal and shows its panel under the provider; one per provider and host at a time. Cancel drops the account it was adding.
  - The built-in login can't be renamed.
  - Rename is an inline field.
  - Remove and Sign out each confirm first.
- Session rows: show the account label, the one a switch moves to included, when that provider has more than one account on the host.
- `pk/chat/composer/account_chip.rs`: the chat's chip and its popover (decision 13).
- `pk/modals/add_project/accounts.rs`: the Accounts field of Project settings; `pk/settings/projects.rs` names a project's picks (decision 16).
