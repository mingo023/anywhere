How-to guide

Review and commit an agent's changes

Read what an agent changed, compare its worktree with a branch, commit, and take the work through a pull request, beside the session that made the change.

The right edge of the window has four buttons. They open the sessions, the files, Changes, and Pull request for the worktree on screen. Changes has a branch icon, and Pull request has the GitHub icon. Click the same button again to close the panel.

Read the diff

  1. Select the session or worktree in the sidebar.
  2. Click the branch icon on the right edge to open Changes. You can also click the worktree's +N −M count in the sidebar.
  3. Click a file under Changes or Staged Changes to open its diff. Double-click to keep the diff open.

To find any file in the worktree, press ⌘P.

Compare with a branch

By default, Changes shows uncommitted changes. To see everything a worktree changed against a branch, as a pull request shows it:

  1. In the Changes header, click the scope switch, which reads Uncommitted.
  2. Pick a branch. The worktree's base branch is tagged base. Type in Search branches… to filter.

The switch now reads vs <branch>. The list shows the files changed from where the worktree left that branch to its latest commit. This view is read-only and has no commit box. Each worktree remembers its own choice. If the branch goes away, the view goes back to the base branch.

To go back, click the switch and pick Uncommitted.

Stage, discard, and commit

  1. Hover over a file or a section header to show its buttons. The plus stages, the minus unstages, and the discard button discards.
  2. Type a message in the commit box.
  3. Press ⌘↩, or click Commit.

If nothing is staged, the button reads Commit All and commits every changed file. To commit only staged files, set Settings › Git & GitHub › If nothing is staged to Staged only.

The arrow next to the commit button has more choices: Commit & Push, Commit, push and create PR, and Amend Last Commit.

WarningDiscarded changes can't be restored. Anywhere asks first, and says how many untracked files it will delete.

To have an agent write the commit message, turn on Settings › Git & GitHub › Write commit messages with AI. A sparkle button then shows in the commit box.

Push and open a pull request

Pull request features use the GitHub command line tool, gh. Install it and run gh auth login. Settings › Git & GitHub › GitHub CLI shows whether it is ready.

  1. When nothing is left to commit, the commit box shows how many commits are ready. Click Push n commits.
  2. Click Create Pull Request.
  3. Fill in Title and Description, or wait for the agent to write them.
  4. Click Create PR. To open a draft, choose Create draft pull request from the button's menu.

Use the pull request card

Click the GitHub icon on the right edge, or the #123 chip in the Changes header, to open the Pull request panel. The icon takes the pull request's state colour, and a red dot shows when it needs something from you.

The card's header shows the title, the number, and a verdict such as Ready to merge, Changes requested, or the number of checks that failed. The button with the external-link icon opens the pull request on GitHub. Below the header are three sections.

  • Checks lists the checks. A failed check has Log to read its output and Send to hand it to the agent.
  • Review shows approvals, requested changes, and up to three open comments, each with Send.
  • Merge says what stands in the way, such as conflicts or checks that haven't passed.

When there is more than one thing to fix, Send all sends them all to the agent at once.

Merge

  1. Pick the merge method from the arrow on the merge button: Squash and merge, Create a merge commit, or Rebase and merge. Squash is the default.
  2. Click the merge button. It works only when the card says the pull request is ready.

Delete the worktree after merging is on by default. It keeps the branch. If the branch conflicts with the base, the merge button changes to Resolve with and the agent's name. For a draft, it changes to Ready for review.

Pull request links in a chat

A link to a GitHub pull request in a chat shows as a chip. If the pull request belongs to one of your worktrees, the chip shows its title, number, and status. Hover over the chip to open a card with Open in panel and Send to the agent.
