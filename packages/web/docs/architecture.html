Explanation

About how Anywhere runs on your machines

Anywhere has no Anywhere account and no Anywhere server that your sessions pass through. The program that runs your agents runs on your own machine, and the apps talk to it directly. The one service the project runs is a push relay for iPhone notifications, and it stores no device tokens.

All of it is in one MIT-licensed repository, mingo023/anywhere. There is no paid tier and no license check in the code. This page says what runs where, and lists every connection Anywhere makes to the network, so you can check that against the source.

pocketd runs the sessions

pocketd is a Go program, in packages/pocketd. It owns the terminals, the sessions, the Board, the automations, and the connection to the phone. The desktop app shows what pocketd runs. It doesn't run agents itself.

That split is why agents keep running after you close the window, and why automations fire while the app is closed. pocketd starts at login as a background service, and it outlives the app:

  • On macOS it ships inside the app as Contents/Library/Helpers/AnywhereDaemon.app, registered as a login item. A moved or deleted app takes its service along.
  • On Linux it is a systemd user service.
  • On Windows it is a scheduled task.

pocketd keeps its data in ~/.coding-pocket. It listens in three places, all on your machine or your tailnet:

  • A Unix socket, ~/.coding-pocket/pocketd.sock, for the desktop app and the anywhere command. On Windows, also 127.0.0.1 port 4519.
  • Port 4517 on 127.0.0.1 and on the machine's Tailscale addresses, for phones. Set listen to loopback to keep it off the tailnet.
  • A port on 127.0.0.1 for the orchestrator's MCP server, which chat agents use to delegate work.

When an update replaces pocketd, it hands its live terminals and agents to the new program inside the same process instead of restarting. Clients see a reconnect, and no terminal or agent stops. The cost is that a bug in that handover path would kill the terminals, so it is dry-run first. Windows can't do this, so updating pocketd on a Windows host closes its terminals.

The desktop app is a client

The desktop app, pocket-desktop, is written in Rust with GPUI, in packages/desktop. It talks to pocketd over the Unix socket. It reads git itself, and it calls the gh command for pull requests.

A host you add over SSH runs its own pocketd. pocketd on your machine reaches it through an ssh tunnel to the host's pocketd, and the host's projects show in the same sidebar.

The phone connects straight to the Mac

The iPhone and iPad app, coming soon, is native SwiftUI, in packages/ios. It connects to pocketd on your Mac over Tailscale, with no Anywhere server in between. pocketd refuses to pair a phone until Tailscale is running.

A phone gets less than the desktop app. It never gets to run arbitrary commands or read arbitrary files. Every git, GitHub, and file request names a registered project, worktree, or Local, and pocketd runs a fixed command for it.

One protocol

The desktop app, the phone, and the anywhere command all speak the same WebSocket protocol to pocketd. packages/protocol is its TypeScript schema, kept in step with pocketd's Go types and the iPhone app's Swift types. It is a specification, not a running service. Each release still speaks the protocol of the release before it, so a phone and a Mac don't have to update at the same moment.

The push relay

A push notification to an iPhone has to go through Apple, signed with the app's Apple push key. Putting that key in every copy of pocketd would hand it to every user, so pocketd never holds it. A small relay, packages/pushrelay, holds the key instead. The project runs it at https://push.getanywhere.dev.

The relay is built to know as little as possible:

  • It stores no device tokens. The phone registers its token with the relay and gets back a handle, which carries the token sealed under a key only the relay has. The phone gives that handle to pocketd.
  • Alert text is encrypted with a key that only the phone and pocketd share. The relay forwards it without being able to read it.
  • It keeps only rate counters, in memory. Its logs hold each send's kind, status, size, and Apple id, never its content.
  • Live Activity updates are the exception to the encryption. They pass through Apple unencrypted.

The relay's source and an example deployment are in packages/pushrelay. pocketd config set push.relay https://<host> sends pocketd's pushes to another relay. The iPhone app registers with https://push.getanywhere.dev and has no setting for another relay.

pocketd sends a push only to a handle that a paired phone registered. Without a paired phone, it has nothing to send.

Every network connection

This is every connection that Anywhere's own code makes, apart from links you open yourself. The agents you run make their own connections to their providers. Those are the agents' business, not Anywhere's.

FromToWhy
pocketdThe push relayTo send a push to a paired phone.
pocketdapi.anthropic.com and chatgpt.comTo read the usage of your Claude Code and Codex accounts for the meters in Settings › Accounts, with the agents' own sign-in.
pocketd and the desktop appYour git remotesTo fetch the base branch when creating a worktree, and to push when you push.
pocketd and the desktop app, through ghGitHubTo show and act on pull requests and checks.
The macOS appGitHub ReleasesTo check for updates, at launch and every 6 hours by default. Change it in Settings › General › Check for updates.
pocketd, through sshHosts you addTo reach their pocketd, and to install it.
A host you addGitHub ReleasesTo download pocketd during install or update.
pocketd and the desktop appThe agent command line tools you installedTo list each agent's models, to name a new branch from the prompt, and to write commit messages when you turn that on. The agents then reach their own providers.
The iPhone appYour Mac, over TailscaleEverything the app shows and does.
The iPhone appThe push relayTo register for notifications.

Anywhere's own code has no analytics, telemetry, or crash reporting.
