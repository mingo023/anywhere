Reference

The anywhere command

anywhere is pocketd run under the name anywhere. It starts sessions, sends prompts, reads replies, and edits Board tickets. The sessions it starts show in the desktop app like any other.

To install the command, see Install the anywhere command.

Synopsis

anywhere project list [--json]
anywhere session list [--json]
anywhere session read [--limit 200] [--json] <id>
anywhere session create [--project <name|path>] [--worktree <name> | --new-worktree [<name>] [--base <branch>]] [--provider <agent>] [--access settings|ask|edits|auto|full] [--prompt <text>]
anywhere session prompt <id> <text|->
anywhere session close <id>
anywhere session wait [--timeout 30m] <id>
anywhere ticket create [--project <name|path>] [--provider <agent>] [--base <branch>] [--title <text>] [--start] <prompt|->
anywhere ticket list [--json]
anywhere ticket read [--json] <id>
anywhere ticket update [--title <text>] [--provider <agent>] [--base <branch>] [--prompt <text|->] <id>
anywhere ticket delete <id>

Conventions

  • Flags go before or after the positional arguments.
  • <agent> is one of claude, codex, cursor, grok, opencode, pi, omp, fx, hermes, or antigravity. Left out, it is claude. See Supported agents.
  • A text argument of - reads the text from standard input.
  • --json prints indented JSON instead of a table.
  • --project takes a project's name or its path. Without it, the command uses the project whose main checkout or worktree holds the current directory.
  • The command talks to pocketd over its Unix socket, ~/.anywhere/pocketd.sock. The POCKETD_SOCK environment variable sets another path. If pocketd isn't running, the command fails with can't reach Anywhere's service at <socket>.

project list

anywhere project list [--json]

Prints one line per project: its name and its path.

session list

anywhere session list [--json]

Prints one line per session, the most recently updated first: its id, status, agent, project, and title.

session create

anywhere session create [--project <name|path>] [--worktree <name> | --new-worktree [<name>] [--base <branch>]] [--provider <agent>] [--access settings|ask|edits|auto|full] [--prompt <text>]

Starts a chat session and prints its id.

FlagDefaultDescription
--project <name|path>The project holding the current directoryThe project to start the session in.
--worktree <name>The main worktreeAn existing worktree of the project, by name.
--new-worktree [<name>]OffCreates a new worktree for the session. Without a name and with --prompt, pocketd names the branch from the prompt. Can't be used with --worktree.
--base <branch>The project's defaultThe branch the new worktree starts from. Only with --new-worktree.
--provider <agent>claudeThe agent to run.
--access <mode>settingsThe access mode: settings, ask, edits, auto, or full. settings uses the agent's own permission settings. See Access modes.
--prompt <text>NoneThe first prompt.

With --prompt, the command prints the id and then waits up to 30 seconds for the turn to start. If the turn doesn't start in that time, it fails with session <id> didn't start a turn within 30s. The session still exists.

session prompt

anywhere session prompt <id> <text|->

Sends the text to the session. If the session reports its status, the command waits up to 30 seconds for the turn to start, so a session wait right after it waits for that turn.

session read

anywhere session read [--limit 200] [--json] <id>

Prints the agent's last reply: everything it said after the last user message.

FlagDefaultDescription
--limit <n>200How many timeline items to fetch, from 1 to 500.
--jsonOffPrints the fetched timeline items as JSON instead of the last reply.

session wait

anywhere session wait [--timeout 30m] <id>

Waits until the session is no longer Working, then prints one word and exits with its code. --timeout takes a duration such as 90s, 30m, or 2h. The default is 30m.

WordExit codeMeaning
done0The turn ended. The session is Done, or Idle if someone was looking at it.
failed3The turn ended with an error.
needsYou4The agent is waiting for an answer or a permission.
timeout5The timeout passed first.
closed6The session closed.

If the session isn't Working when the command starts, it reports the current state right away. A session that doesn't report its status, such as an agent other than Claude Code or Codex running in a terminal, fails with exit code 1 and session <id> doesn't report its status.

session close

anywhere session close <id>

Closes the session and its terminal.

ticket create

anywhere ticket create [--project <name|path>] [--provider <agent>] [--base <branch>] [--title <text>] [--start] <prompt|->

Adds a ticket to the Board and prints its id.

FlagDefaultDescription
--project <name|path>The project holding the current directoryThe ticket's project.
--provider <agent>claudeThe agent that works on the ticket.
--base <branch>The project's defaultThe branch the ticket's worktree starts from.
--title <text>The prompt's first lineThe title, 1 to 200 characters.
--startOffStarts the ticket. It waits in Queued until a slot is free.

ticket list

anywhere ticket list [--json]

Prints one line per ticket: its id, state, agent, project folder, and title. For a started ticket, the state is its session's status.

ticket read

anywhere ticket read [--json] <id>

Prints the ticket's title, then its state, agent, and folder, then its prompt.

ticket update

anywhere ticket update [--title <text>] [--provider <agent>] [--base <branch>] [--prompt <text|->] <id>

Changes only the fields you pass. Pass at least one flag. An empty --base "" clears the base branch.

ticket delete

anywhere ticket delete <id>

Deletes the ticket.

Inside an Anywhere terminal

A process that runs inside an Anywhere terminal can only read. project list, session list, session read, and session wait work there. Every other command fails with this message:

a process inside an Anywhere terminal can only read sessions; run this from outside Anywhere

Exit codes

CodeMeaning
0Success. For session wait, done.
1The command failed. The error is printed after anywhere:.
2Bad command line. The usage is printed.
3session wait: failed.
4session wait: needsYou.
5session wait: timeout.
6session wait: closed.

The agent skill

Installing the command also installs a skill that tells Claude Code and Codex how to use it. pocketd skill install writes the skill to these files:

  • ~/.claude/skills/anywhere/SKILL.md
  • ~/.agents/skills/anywhere/SKILL.md

pocketd settings

Set these pocketd settings with pocketd config set <key> <value>. Run it under the name pocketd, not anywhere, while pocketd is running. The desktop app has controls for some of them, but none for the orchestrator keys and push.relay.
