How-to guide

Plan work on the Board

The Board holds tickets for every project in one place. A ticket is a piece of work for an agent: a title, a prompt, an agent, a project, and the branch it starts from. A started ticket gets its own worktree and session.

To open the Board, click Board in the sidebar, or choose Go to Board in the command palette (⌘K).

Write a ticket

  1. Click the Board's composer, or press N.
  2. Type the work. The first line becomes the title, and the whole text becomes the prompt.
  3. Set the chips: the project, the agent, the base branch, and optionally a priority and a label.
  4. Click Add to To do, or press Return.

The ticket goes into To do. Open it to change its title, prompt, agent, project, or base branch.

Only git repositories can hold tickets.

Start a ticket

Do one of these:

  • Click Start on the ticket's card.
  • In the composer, press ⌘↩ to add the ticket and start it at once.
  • Drag the ticket to Working.

A started ticket goes to Queued first. When a slot is free, pocketd creates the ticket's worktree from its base branch and starts its session there. From then on, the card sits in the column that its session's status says. Board sessions start with the agent's own permission settings.

Limit how many tickets run at once

pocketd starts the next queued ticket while fewer tickets than the limit are starting, working, or need you. The limit is 4 by default and can be from 1 to 8.

  1. Open the Board's Display menu.
  2. Change Work on at once with the minus and plus buttons.

The Working column's header shows how many slots are in use.

Follow tickets through the columns

ColumnHolds
To doTickets not started.
QueuedStarted tickets waiting for a slot.
WorkingTickets whose session is starting or whose agent is running a turn.
Needs youTickets whose agent is waiting for an answer, failed, or was stopped.
DoneTickets whose turn ended and that nobody has seen yet.
In reviewIdle tickets.
MergedTickets closed because their pull request was merged.
ClosedOther closed tickets. Hidden unless Show closed tickets is on in the Display menu.

You can drag a card only while it has no session: from To do to Queued or Working, and from Queued back to To do.

Close a ticket

Open the ticket's menu and click Close ticket. The ticket's worktree and session stay. A merged pull request or a deleted worktree also closes the ticket. To bring a closed ticket back, click Restore.

Manage tickets from the command line

The anywhere command adds, reads, edits, and deletes tickets. For example, to add a ticket and start it:

anywhere ticket create --project app --start "Fix the flaky login test"

See ticket create and the other ticket commands.
