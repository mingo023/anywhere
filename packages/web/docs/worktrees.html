How-to guide

Start an agent in a new worktree

A worktree gives an agent its own branch and its own copy of the files, so several agents can work on one project without touching your branch or each other's.

A new worktree starts on a new branch of the same name. Its folder name stays the same if the branch changes later.

Start a session in a new worktree

  1. Press ⌘⇧N, or click the + on the project's row in the sidebar. The new session page opens with Worktree picked.
  2. Check the project chip and the agent.
  3. To start from a branch other than the default, click the branch chip and pick a branch. Branches only on the remote show as origin/<name>.
  4. Type the prompt and press Return.

Anywhere shows its progress under Creating worktree: Fetching latest changes, Creating git worktree, Copying configuration, Setting up, and Starting agent. Then the session opens in the new worktree, which the sidebar lists under the project.

The new worktree gets a generated name. To start every new session in a worktree, set Settings › Agents › New sessions › Runs in to Worktree.

Worktree or LocalOn the new session page, the checkout chip offers Worktree and Local. A worktree has its own branch and copy of the files. A Local is a new place over the project's checkout, so it shares the files and the branch. Pick Local when you want the agent to work on your current branch.

Check out an existing branch

To work on a branch that already exists instead of a new one, open the branch chip, hover over the branch, and click Open worktree.

Start from a pull request

Click the pull request button next to the branch chip and enter 123, #123, or a pull request URL. Press Return to link it. The page shows based off PR #123, and the session starts in a new worktree based on that pull request.

From the command line

anywhere session create --new-worktree --base main --prompt "Fix the flaky login test"

See session create.

Run setup commands in new worktrees

A new worktree has the committed files only. Setup commands install dependencies or build what the agent needs before it starts. Anywhere takes the first setup it finds, in this order:

  1. The commands in the project's settings. Open the project's menu in the sidebar, click Project settings…, and fill in When one is created under Worktrees.
  2. The setup list in .anywhere/config.json. Anywhere reads the file from the new worktree first, then from the project's own checkout.
  3. The script .anywhere/setup.sh, run with bash. Anywhere looks in the new worktree first, then in the project's own checkout. Anywhere never runs this script on Windows.

To commit setup commands with the repository, add .anywhere/config.json:

{
	"setup": ["pnpm install", "cp .env.example .env"]
}

The commands run as one script, one line each. If the file isn't valid JSON, Anywhere skips it.

Or add a script at .anywhere/setup.sh. The script can be in .gitignore. Then new worktrees lack it, and the copy in the project's own checkout runs.

How setup runs

  • Setup runs in the session's own terminal, in the new worktree, in your login shell, before the agent starts. Anything it exports reaches the agent.
  • Setup gets three environment variables. ANYWHERE_ROOT_PATH is the path of the project's own checkout. ANYWHERE_WORKSPACE_PATH is the path of the new worktree. ANYWHERE_WORKSPACE_NAME is the worktree's folder name.
  • Setup runs only when Anywhere creates a worktree. It doesn't run for a Local or an existing worktree.
  • To watch the output, click View output on the progress page.

If a setup command fails, the agent doesn't start. Anywhere shows Couldn't start the session with Setup exited and the exit code, and the terminal stays open so you can read it. The worktree stays.

Copy files into new worktrees

Before setup, Anywhere copies the project's root .env* files into the new worktree. To copy other untracked files, list their paths, one per line, in a .worktreeinclude file at the project's root. Lines that start with # are comments.

Run commands when a worktree is deleted

Teardown works like setup and runs before Anywhere removes a worktree. Anywhere takes the first it finds: When one is deleted in the project's settings, the teardown list in .anywhere/config.json, or .anywhere/teardown.sh.

Choose where worktrees go

New worktrees go in ~/.anywhere/worktrees/<project>/<name>. To use another folder:

  1. Open Settings with ⌘, and select Projects.
  2. Under Locations, find Worktree folder and click Choose….
  3. Pick the folder.

The setting applies to every project on this machine. To go back, click Use default. Projects on another machine always use that machine's ~/.anywhere/worktrees.

Delete a worktree

  1. Right-click the worktree in the sidebar, or open its ··· menu.
  2. Click Delete worktree….
  3. To delete its branch too, select Also delete branch.
  4. Click Delete.

WarningDeleting a worktree closes its terminals and removes its folder. Uncommitted files and commits that are on no other branch are lost. The branch stays unless you select Also delete branch.

You can't delete a project's main worktree.

Add worktrees you made outside Anywhere

If git has worktrees of the project that the sidebar doesn't list, the project's menu shows Import 1 worktree or Import n worktrees. Click it to add them to the sidebar.
