Script coding agents from your shell with anywhere session wait

By Minh Ngo · Published 18 November 2026 · Updated 18 November 2026

Anywhere's anywhere command lets you script coding agents from any shell. It can create a session in a new git worktree, send a prompt, read replies and wait for a result. anywhere session wait exits 0 when the agent is done, 3 when it failed, 4 when it needs you, 5 on timeout, and 6 if the session closed.

This post is a set of recipes. Every flag and exit code here is in the command reference.

Install the anywhere command

anywhere is pocketd, Anywhere's background service, run under another name. Sessions it starts show in the desktop app like any other.

  • macOS. Open Settings › General, find Command line tool under Startup & background, and click Install. Anywhere links /usr/local/bin/anywhere to the pocketd inside the app. The button is only in release builds.
  • Linux. Link anywhere to the pocketd in the unpacked Anywhere folder, then install the skill: 
    ln -s "$PWD/Anywhere/pocketd" ~/.local/bin/anywhere
Anywhere/pocketd skill install

Installing also writes a skill to ~/.claude/skills/anywhere/SKILL.md and ~/.agents/skills/anywhere/SKILL.md, which tells Claude Code and Codex how to use the command. Check it from a new terminal outside Anywhere:

anywhere project list

The command talks to pocketd over ~/.coding-pocket/pocketd.sock. Set POCKETD_SOCK to use another path. If pocketd isn't running, it fails with can't reach Anywhere's service at <socket>.

Start a session in a new worktree and send a prompt

From inside your repository:

id=$(anywhere session create --new-worktree --base main --provider claude \
  --prompt "Fix the flaky login test and run the test suite")
echo "$id"

What happens:

  • The command starts a chat session in a new worktree off main and prints the session id.
  • Without --project, it uses the project whose checkout or worktree holds the current directory.
  • With --new-worktree and no name, pocketd names the branch from the prompt.
  • With --prompt, it waits up to 30 seconds for the turn to start. If it doesn't start, the command fails with session <id> didn't start a turn within 30s, and the session still exists.
  • --access sets what the agent may do without asking: settings (the default, the agent's own settings), ask, edits, auto, or full.

--provider takes one of ten ids: claude (the default), codex, cursor, grok, opencode, pi, omp, fx, hermes, or antigravity. Two of them differ from the command they run: cursor runs cursor-agent, and antigravity runs agy.

Follow-up prompts go to the same session. A text argument of - reads standard input, which is handy for piping in context:

anywhere session prompt "$id" "Now add a regression test for it"
git log -5 --oneline | anywhere session prompt "$id" -

To print the agent's last reply, everything after your last message:

anywhere session read "$id"

Wait for a result and branch on the exit code

anywhere session wait [--timeout 30m] <id>

session wait waits until the session is no longer Working, then prints one word and exits with its code. --timeout takes a duration such as 90s, 30m, or 2h. The default is 30m.

WordExit codeMeaning
done0The turn ended. The session is Done, or Idle if someone was looking at it.
failed3The turn ended with an error.
needsYou4The agent is waiting for an answer or a permission.
timeout5The timeout passed first.
closed6The session closed.

Exit code 1 means the command itself failed, and 2 means a bad command line. If the session isn't Working when the command starts, it reports the current state right away. A session that doesn't report its status, such as an agent other than Claude Code or Codex running in a terminal, fails with exit code 1. Sessions that session create starts are chats, and every agent reports its status from a chat.

A complete script: start Codex on a task, wait, and act on the result.

#!/bin/sh
id=$(anywhere session create --new-worktree --provider codex \
  --prompt "Fix the flaky login test and run the test suite") || exit 1

anywhere session wait --timeout 45m "$id"
case $? in
  0) anywhere session read "$id" ;;
  3) echo "agent failed: $id" >&2; exit 1 ;;
  4) echo "agent needs you: $id" >&2; exit 4 ;;
  5) echo "still working after 45m: $id" >&2; exit 5 ;;
  *) echo "session ended: $id" >&2; exit 1 ;;
esac

A Needs you result isn't a dead end. The session waits in the Inbox, with a banner, until you answer it in the app. After you answer, run session wait again to wait for the rest of the turn.

To fan out, start several sessions first and wait on each. They run at the same time; only the waits are in order:

a=$(anywhere session create --new-worktree --provider claude --prompt "Migrate the settings page to the new form API")
b=$(anywhere session create --new-worktree --provider codex --prompt "Raise test coverage of src/billing")
anywhere session wait --timeout 1h "$a"; ra=$?
anywhere session wait --timeout 1h "$b"; rb=$?
echo "claude: $ra, codex: $rb"

Tickets from the CLI

The Board is the queue version of the same idea. A ticket is a prompt, an agent, a project, and a base branch. A started ticket waits in Queued until a slot is free, then gets its own worktree and session. The Board runs four at once by default.

anywhere ticket create --project app --provider codex --start "Fix the flaky login test"
cat tasks/search.md | anywhere ticket create --title "Search index" --start -
anywhere ticket list

ticket list shows each ticket's state, which for a started ticket is its session's status. ticket read, ticket update, and ticket delete do the rest. Use tickets when you want to queue more work than should run at once; use session create when you want to wait on a result in the same script.

Scheduled automations vs your own cron

For a prompt on a schedule, Anywhere has automations built in: chosen weekdays at a time, or a repeat from every 5 minutes to every 7 days. pocketd starts each run as an ordinary session, keeps firing while the desktop app is closed, keeps a run history, and handles a run that needs you like any other session. No script needed.

Reach for cron, or a CI runner on a machine where Anywhere runs, when you want logic around the run: chain steps, act on the exit code, or post the reply somewhere else. A weekday morning job could look like this:

0 9 * * 1-5  cd ~/code/app && /usr/local/bin/anywhere session create --new-worktree --prompt "Update dependencies and run the tests" >> ~/agents.log 2>&1

Three things to keep in mind:

  • Use the full path to anywhere. Cron's PATH is usually shorter than your shell's.
  • pocketd must be running on that machine, because the command talks to its socket.
  • Run it from outside Anywhere. A process inside an Anywhere terminal can only read: project list, session list, session read, and session wait work there, and every other command fails.

Because pocketd owns the sessions, none of this needs the window open. See Keep coding agents running after you close the window. For agents that hand work to each other from a chat, see delegation.

FAQ

Can I start a Claude Code agent from a shell script?

Anywhere's anywhere command lets you script coding agents from any shell. It can create a session in a new git worktree, send a prompt, read replies and wait for a result. anywhere session wait exits 0 when the agent is done, 3 when it failed, 4 when it needs you, 5 on timeout, and 6 if the session closed.

How do I wait for a coding agent to finish in CI or cron?

Run anywhere session wait with the session id. It waits until the session is no longer Working, prints one word and exits with its code: 0 for done, 3 for failed, 4 for needsYou, 5 for timeout and 6 for closed. The default timeout is 30m; pass --timeout with a duration such as 90s, 30m or 2h to change it. The command talks to pocketd, so it runs on a machine where Anywhere's service is running.

Can agents use the anywhere command themselves?

Yes, within limits. Installing the command also installs a skill that tells Claude Code and Codex how to use it. A process inside an Anywhere terminal can only read: project list, session list, session read and session wait work there. To have a chat start other sessions, use delegation, which goes through pocketd's orchestrator over MCP.
